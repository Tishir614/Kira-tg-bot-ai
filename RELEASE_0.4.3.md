# KiraBot 0.4.3 — стабильность и безопасное обновление

База: kira-bot-mature-mode-2.0-0.4.2.zip. Схема БД и имена существующих команд сохранены. Модуль `bot/handlers/masturbate` и связанные проверяемые функции БД не изменены.

## Изменения

- Авто-ГС: исправлен неверный атрибут часового пояса; исправлен вызов AI, добавлен режим без чтения и записи памяти; экранируется подпись. Старые quiet hours 09–23 и интервал 3 часа сохранены.
- Команды: распознаётся `авто гс вкл` с пробелом; AI можно снова включить фразой `Кира, ии вкл`, когда он отключён; длинный текст отправляется без HTML-разметки.
- AI: запросы одного пользователя в одном чате обрабатываются последовательно, память не перемешивается при параллельных сообщениях; блокировки удаляются после завершения/отмены. Разные диалоги продолжают работать параллельно.
- Голос: ограничено время одного потока Edge TTS; HTTP fallback принимает только аудио и ограничивает размер ответа 20 МБ; `/voice_ai` отправляет текст до озвучки, сохраняет его при отказе TTS и отклоняет входные файлы больше 20 МБ.
- Mature-профиль: отображение личных настроек только в личке; сохраняется регистр стоп-слова и границ; исправлен разбор `limits:`. Сюжетные промпты и существующие RP-команды сохранены.
- Поиск/медиа: таймаут поиска картинок и параметры ограничения сетевых ожиданий yt-dlp; временный файл прямой загрузки удаляется также при отмене запроса.
- Диагностика: уникальный временный файл проверки записи; недоступная папка данных не обрывает отчёт; версия и часовой пояс в `/doctor`; фильтрация известных секретов в диагностике и сообщениях стандартного логгера. Это не гарантия удаления всех возможных секретов из сторонних трассировок.
- Обновлятор: предварительная проверка ZIP, путей, ссылок, размера, Python и Bash; блокировка одновременной установки; постоянная резервная копия; откат заменяемых файлов при обычной ошибке копирования. `.env` и `static` не заменяются содержимым архива. Неизвестные файлы вне заменяемых каталогов сохраняются.
- Повторный setup сохраняет существующие значения `.env` и добавляет только отсутствующие настройки. Для изменения уже заданных параметров редактируйте `.env` вручную. Обновление не требует повторного setup.

## Обновление с 0.4.2

Требуется Python 3.11+ на хосте; бот продолжает использовать Python 3.12 в Docker. Выполняйте команды в прежней папке установленного проекта. Не меняйте Docker Compose project name: от него зависят имена томов.

1. Сохраните новый ZIP на сервере, например `/root/kira-bot-0.4.3.zip`.
2. Остановите контейнер Киры и сделайте отдельную копию рабочей базы из Docker-тома:

```bash
cd /opt/kira/kira-bot-master
docker compose stop kira
umask 077
KIRA_BACKUP_DIR="$(mktemp -d /root/kira-data-before-0.4.3-XXXXXX)"
docker compose cp kira:/app/static "$KIRA_BACKUP_DIR/static"
cp -p .env "$KIRA_BACKUP_DIR/.env"
```

Если копирование не удалось — не продолжайте обновление до получения резервной копии. Установочный архив не содержит вашей базы. Для установки без Docker остановите процесс бота и скопируйте используемый DATA_DIR.

3. Запустите новый установщик отдельно: старый `upgrade.sh` версии 0.4.2 небезопасен и для этого перехода не нужен.

```bash
KIRA_INSTALLER="$(mktemp /tmp/kira-upgrade-XXXXXX.py)"
unzip -p /root/kira-bot-0.4.3.zip kira-bot-master/tools/safe_upgrade.py > "$KIRA_INSTALLER"
python3 "$KIRA_INSTALLER" /root/kira-bot-0.4.3.zip "$PWD"
```

Продолжайте только после сообщения об успешном обновлении. Сохраните показанный путь резервной копии.

4. Запустите контейнер в той же папке:

```bash
docker compose up -d --build kira
docker compose logs --tail=100 kira
```

Работающий Ollama и существующие тома сохраняются. Если Ollama ранее был остановлен, запустите его своим прежним профилем `docker compose --profile ollama up -d ollama`.

5. Проверки в Telegram: `/doctor`, `/doctor full`, `/voice_auto test`, `/mature profile` в личке, обычный AI-запрос.

## Откат и ограничения

Резервная копия исходников создаётся рядом с проектом с правами каталога 700. Содержимое host `static` входит в эту копию; Docker-том копируется отдельно на шаге 2. При ошибке замены файлов установщик восстанавливает их автоматически. Отключение питания, SIGKILL и исчерпание диска во время самого отката могут потребовать ручного восстановления.

Для ручного отката остановите `kira`, восстановите код из выведенного каталога резервной копии в прежнюю папку и выполните `docker compose up -d --build kira`. Версия 0.4.3 не меняет схему БД, поэтому откатывать данные обычно не требуется. Не используйте `docker compose down -v`.

Тесты выполняются локально с искусственными ответами сервисов. Реальная доставка Telegram, доступность AI/TTS/поисковых провайдеров, сборка Docker на сервере и миграция вашей рабочей базы требуют проверки в целевом окружении. Проверка адресов yt-dlp из исходной версии не гарантирует блокировку всех внутренних перенаправлений; для недоверенных публичных пользователей ограничивайте исходящую сеть контейнера.
